An optimization solver
written from the mathematics.

A solver for the decisions a refinery makes every week: which crudes to buy, how hard to run each unit, how to blend. Linear, mixed-integer and convex quadratic programs, in C++ from the textbooks, with no code from any existing solver, and every answer re-checked by a separate program before it is reported.

Three questions

What an evaluator usually wants to know first.

Is it really from scratch?

Yes. No library the binary links is an optimization solver; the problem page lists them for the CPU and the GPU build. A CI job prints the link line and fails if a solver library ever appears. Check it in two minutes →

Are the answers right?

Every reported answer is re-derived by a Python checker that reads only the model file and the solution file. An infeasible verdict carries a proof the checker verifies too. Run the checker →

How does it compare?

Same answers as HiGHS on all 50 medium Netlib models. Time depends on the machine: 0.99x HiGHS's in total on a rented 7-vCPU EPYC 7542 node, a median of 2.01x to 2.12x on a laptop; neither reading is quoted alone. Behind on large mixed-integer proofs and on the biggest LPs, and the site says by how much. Ahead and behind →

What is new

Ten additions on main, each with its default and its result.

Each is on main at 3f8256e. Most are off by default until a clean A/B on main says they earn it; the solver page gives every one its option, its default and its result, losing results included.

  • Verifier-gated engine race · three LP engines at once; an answer wins only after it passes the verifier's own check. Off.
  • A checkable proof of a MILP optimum · written in the VIPR format and checked in exact rational arithmetic by a separate program. Off.
  • Safe dual bounds · every node pruned on a bound that holds whatever the LP tolerances did. Off.
  • Exact rational re-check of an LP basis · declines more often than it verifies on realistic models, and says so. Off.
  • Global optimum for bilinear pooling · spatial branch and bound; Haverly's pool reaches the published 400. Off, non-convex models are refused by default.
  • GPU node bounding and GPU heuristics · measured on committed runs, and none earns a default there. Off.
  • Replayable evidence bundle · one zip with the model, options, binary identity, log and answer, re-checked on replay.
  • Parametric LP and infeasibility repair · walk a price or a limit across its breakpoints; find the smallest relaxation that makes a plan possible.
  • PuLP, Pyomo and CVXPY adapters · an existing model changes one line, the solver call.
  • Deterministic mode · the same numbers from two runs of one build, no decision taken on the clock. Off.
